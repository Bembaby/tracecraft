# TCS learning path

October 29, 2026. `#tcs` adds 25 original lessons covering the 24 requested discussion topics. Byte formatting is a separate lesson before object composition. This is a study path in the existing alpha, with beginner links, vocabulary, worked examples, saved predictions, one recognition check per lesson, private notes, read marks and an eight-question mixed review. It does not reproduce an external assessment or claim employer approval.

| Sequence | Lessons |
|---|---|
| Python building blocks | Guards/return, first-class and higher-order functions, deque/list/stack/tree choices, exact byte formatting, classes/special methods/composition, mutual recursion |
| Data contracts and SQL | Incomplete requirements, SELECT/WHERE/ORDER BY, LEFT JOIN/NULL-aware counts/grouping/ties |
| Git snapshots | HEAD, index and working tree; staged versus unstaged differences and reset boundaries |
| HTTP and browser requests | Resource URLs/methods/redirects, status/error contracts, caching directives, fetch/status/JSON/body stages |
| Security boundaries | Private offline caches and exact origins, XSS output contexts, bound SQL and allowlisted structure, OAuth callback binding, Firebase configuration/authentication/authorization |
| AI and evaluation | Stratified splits and imbalance, regularization/validation, prompt examples versus training, RAG evaluation dimensions, grounding/abstention and mitigation limits |
| Trace and review | Loop progress, invariants/back edges, mixed recognition review and changed code practice |

Eight new Python tasks execute in the existing CPython worker: deque commands, byte formatting, objects, callbacks, guards, mutual recursion, origin parsing and loop progress. Two new SQLite tasks check a strict threshold and a zero-child join. Each has an exact contract, edge fixtures, a deliberate bug, solution, explanation, complexity and tests. Total executable library: 51 Python, 40 SQLite and ten browser Java tasks.

Security, Git and AI examples are authored walkthroughs and recognition practice. They do not execute destructive Git commands, configure a remote provider, train a model, run a RAG service or assess clinical safety. Python worked outputs are checked with CPython; illustrative HTTP/protocol/model examples are explicitly described. Reading, recognition, written self-assessment and latest runtime checks remain distinct. The mixed review repeats known questions and makes no retention claim.

`tcs-state.mjs` validates optional version-1 state inside training progress. Known IDs, bounded notes/predictions and current-version recognition records survive complete and training backups plus reviewed account sync. It rejects unknown fields, stale checked status and invented correctness. Save failures remain visible on lessons, overview and review routes. Learner notes and the private source export are not copied into public examples.

An independent critique verified the requested topic coverage and corrected fixture display, positive object lengths, exact half-up rounding, raw-label versus rendered-string sorting, SQL final tie order and save-failure navigation. The curriculum corrects several oversimplifications using [URI syntax](https://www.rfc-editor.org/rfc/rfc3986.html), [HTTP caching](https://www.rfc-editor.org/rfc/rfc9111.html), [OAuth security guidance](https://www.rfc-editor.org/rfc/rfc9700.html), [Firebase rules](https://firebase.google.com/docs/rules/basics) and [scikit-learn evaluation guidance](https://scikit-learn.org/stable/modules/cross_validation.html). Primary references are linked in each lesson.
